> 目标（原话）：基于 rust_bevy_lua_game 与 Floniks 的既有能力，开发一款**混合式休闲游戏**；
> 底层由**某个数学公式驱动**，玩法是混合式的；**视觉体验、游戏体验、完整度都要高**。
> 本文回答四件事：这个目标怎么**分解**、玩法怎么**选**（附两路调研结论）、
> 团队怎么**搭**、开发按什么**计划与节奏**推进。
>
> 调研执行于 2026-07-07，两份子报告（混合休闲品类 / 数学驱动玩法先例）的
> 关键结论已内联进本文，来源链接随文标注。

## 〇、设计第一性原则

来自 [Riot Games 游戏设计课](https://www.riotgames.com/zh-cn/artedu/game-design)，作为全程的裁判标准：

1. **理解"快乐"**——先说清这款游戏的乐趣本质是什么（本方案：*看着简单规则涌现出意外结果，并且赢下它*）；
2. **设立明确的目标**——玩家任一时刻都知道"我在争取什么"；
3. **制造对立**——乐趣来自冲突：风险 vs 收益、贪 vs 稳；
4. **美术与设计无缝连接**——视觉不是贴皮，必须服务并放大机制（我们的 WGSL 背景随玩法呼吸、Floniks 风格圣经全局锁定，正是为此）;
5. **迭代 + 立即反馈**——最低成本原型、最快 playtest。我们的对应物：Lua 热重载（秒级）、无头测试（分钟级）、Web 链接（一天内可给真人玩）。

## 一、目标分解

把一句话目标拆成五个可独立验收的子目标：

| # | 子目标 | 含义 | 验收标准 |
|---|---|---|---|
| G1 | **数学核心** | 一个公式/规则系统作为唯一的玩法地基，确定性、可无头断言 | 规则一句话讲清；不变量测试全绿；纯 Lua 实现 60fps |
| G2 | **混合式玩法** | 超休闲核心循环（10 秒可懂、单局 ≤3 分钟）+ mid-core meta 层（成长/收集/每日目标），即 hybrid-casual 公式 | 首局 30 秒内出现第一次"爽点"；本地存档支撑全部 meta |
| G3 | **视觉体验** | 风格圣经锁定的全套 AI 素材 + juice 全覆盖（粒子/震屏/缓动/音效/触觉五件套） | §六 门禁 B/C 类全绿（占位素材清零、所有状态变化有过渡、100% 交互有音效） |
| G4 | **游戏体验（手感）** | 帧率、输入延迟、物理稳定性、难度曲线 | §六 门禁 A/D 类全绿（120Hz、启动 ≤400ms、hang<250ms、输入 ≤1 帧响应） |
| G5 | **完整度** | 不是 demo：完整闭环 = 教学、失败/重试、成长、收集、成就、每日挑战、设置、上架物料 | §六 门禁 E/F 类全绿 + 玩家旅程 28 条检查表逐条过；Web 链接 + TestFlight + 预告片 |

**质量目标定级（应用户要求，2026-07-07 补充）**：本项目的完成度目标不是"能玩的独立小品"，
而是 **AAA 级完成度**——口径见 §六：平台硬指标全绿 + 反馈打磨密度拉满 + Apple Design Awards
六类别作为对外北极星。预算和团队规模学不了 AAA，**打磨水准可以**（Balatro/Monument Valley 已证明）。

**能力对账**（为什么这个目标对我们是"顺势"而非"跳跃"）：

- 引擎侧 P0/P1 已全部关闭（见 [roadmap-and-benchmark.md](./roadmap-and-benchmark.md) §5）：存档 `save/load`、多点触控、相机、三声道音频+音量、图集帧动画、CPU 粒子、tilemap、cutout 骨骼、`track` 埋点，外加 shake/zoom punch/触觉/随玩法呼吸的 WGSL 背景——**G2/G3/G4 需要的原语一件不缺**；
- Floniks 侧 51 种工作流节点已确认可用：文生图/图生图/inpaint/去背/放大（美术）、TextToMusic/TTS（音频）、图生视频/关键帧视频/节拍剪辑/字幕烧录（宣发）、LLM 节点（结构化数据）——**G3/G5 的素材与物料全部有管线**；
- 无头测试传统（13 万断言回归网）——**G1 的"可断言数学核心"正中我们最强的一环**。

## 二、调研结论与玩法选型

### 2.1 品类调研：混合休闲的五条硬约束

（完整报告要点，来源：[Sensor Tower 2025](https://sensortower.com/blog/state-of-mobile-gaming-2025)、[AppMagic](https://appmagic.rocks/blog/hybridcasual-q1-2025/)、[Naavik](https://naavik.co/deep-dives/evolution-of-hybridcasual-deepdive/)、[Supersonic](https://supersonic.com/learn/case-studies/bridge-race)、[Juice it or Lose it](https://gamejuice.co.uk/resources/juice-it-or-lose-it)）

1. **10 秒可懂、一指可玩**——无教程上手，首局 30 秒内第一次爽点；
2. **短循环 + 零挫败重开**——单局 ≤3 分钟，失败即重试（行业以 D1≥40% 为门槛）；
3. **双引擎留存**——局内随机性 × 局外确定性成长，缺一不可（Survivor.io/Archero 的核心配方）；
4. **meta 分层露出**——首日只给核心循环 + 一条升级线，收集/每日挑战在 3–5 个会话内逐步解锁；
5. **Juice 是必需品**——命中三件套（粒子/音效/缓动）+ 震屏 + 连锁反馈是玩家底线预期。

**单机可行的 meta 层**（全部本地 KV 存档即可，`game.save/load` 现成）：永久升级树、皮肤/图鉴收集、
关卡星级、**以日期为种子的每日挑战**（Suika/Balatro 通行做法，天然可测试）、成就、离线收益、最高分。
首发不需要任何后端。

### 2.2 数学核心调研：十个方向的结论

十个候选方向（合并倍增/引力轨道/boids/元胞自动机/波谐振/混沌/黄金角/流场/反应扩散/弹簧软体）按
**规则简洁 / 涌现深度 / 可测试 / 性能 / 触屏适配** 五维打分，Top 3：

| 方向 | 公式 | 商业验证 | 总分 |
|---|---|---|---|
| **合并+物理**（Suika 模式） | `a+a→2a`（指数 2ⁿ）+ 刚体滚动 | Suika 病毒级、2048 现象级 | 23/25 |
| **Boids 群体** | 分离/对齐/凝聚三规则 | Crowd City（Voodoo） | 23/25 |
| **引力轨道** | `F = G·m₁m₂/r²` | Osmos（Apple 年度）、Orbit | 22/25 |

落选但收编为配菜：**黄金角 `θ=n·137.5°`** 作布局/生长视觉工具；**反应扩散**作背景 shader 彩蛋（已有 WGSL 管线）。
明确不做：混沌（不可学习的因果违背休闲"可掌握感"）、全场元胞自动机（数万格/帧，与数百 sprite 架构错位）。

### 2.3 选型：主推概念 + 对照组

**主推 ——《星核熔炉》（Starforge，代号 `forge`）**

> 一句话规则：**单指投放小行星入引力井；同级相撞聚变升级（2ⁿ）；聚变越重、引力越强。**

- **数学核心是两条公式的耦合**：`F = G·m₁m₂/r²`（所有天体被中心引力井 + 彼此拉扯）× `a+a→2a`
  （同级聚变链）。聚变产物质量翻倍 → 引力场随之变强 → 轨道全局重排 → 新的碰撞机会/危险。
  **公式不是背景，是难度曲线本身**：场上质量越大，系统越"紧"，失误代价越高——这就是 Riot 说的"制造对立"
  （贪一次聚变 vs 保住轨道稳定）。
- **失败条件**：天体被甩出屏幕边界（逃逸速度）或坠入中心视界（吞噬）——两个方向的失败天然对称。
- **混合式循环**：局内 = Suika 式投放-连锁-爽点（30 秒–3 分钟）；局外 = 元素图鉴（H→He→…→Fe 聚变链，
  科普感即收集欲）、升级树（初始等级/引力常数微调/复活次数）、日期种子每日挑战、成就。
- **为什么它最适合我们**：两个已验证爆款（Suika + Osmos）的交集；单指竖屏天生；确定性物理 + 固定种子
  → 无头断言不变量信手拈来（能量有界、总质量守恒、聚变单调、大 dt 不跳变——全是既有测试传统的延伸）；
  数百实体在 CPU 甜点区。
- **视觉概念**：深空熔炉。天体 = 发光星核（Floniks 风格圣经：辉光矿物质感），聚变 = 粒子爆发 + zoom punch +
  升调音效 + 重触觉；背景 aurora shader 的 energy 通道直接吃"场上总质量"——**画面亮度随局势升温**，
  美术与机制无缝（Riot 原则 4）。黄金角用于聚变时的碎屑喷射图案。

**对照组 ——《萤火牧歌》（Firefly，代号 `boids`）**

> 一句话规则：**手指是唯一光源；萤火虫群按三规则（分离/对齐/凝聚）追光；一笔引导整群穿越峡谷。**

数百 sprite 恰是引擎甜点区，Crowd City 验证过"群体数量=爽感=经济"。作为 M0 对照原型，
与主推同场 playtest 后定生死（见 §四 M0）——**用原型分胜负，不用会议**（Riot 原则 5）。
两条概念共享"投放/引导 → 观察涌现 → 连锁奖励"循环，meta 层设计可完全复用，切换成本一周以内。

## 三、团队构建

延续本仓库已验证的组织方式（2026-07-07 冲刺：单 agent 流水线 52 分钟清零 9 项能力；双流水线互为对照，
见 roadmap §5）：**人类制作人 + agent 流水线**，每个角色 = 一类 issue + 一套验收标准，而不是一个人头。

| 角色 | 执行者 | 职责 | 交付物 / 验收 |
|---|---|---|---|
| **制作人**（唯一人类） | 马维 | 拍板选型、每日 playtest、"好玩吗"的最终裁判 | 每个里程碑的 go/no-go |
| **主编排 agent** | Claude 主会话 | 拆 issue、调度下述流水线、集成与合并 | issue 树 + 每日集成分支绿 |
| **玩法流水线** | agent（Lua） | `packs/forge.lua`：数学核心、循环、手感、难度曲线 | PACK_SPEC 合规；数值全在 Lua 可热调 |
| **引擎流水线** | agent（Rust） | 仅当 Lua 侧性能/能力不足时开洞（如 `game.field()` 物理批处理、`game.trail()` 拖尾） | LuaCommand 三步走；不为玩法重编 Rust |
| **测试流水线** | agent（Lua/Rust） | 每条玩法不变量的无头断言：质量守恒、能量有界、聚变单调、dt 鲁棒、meta 存档回读 | 测试行数随功能行数同步涨（仓库既成传统） |
| **美术流水线** | agent + Floniks | 风格圣经 → `floniks_manifest.json` → 生成/去背/放大 → 同名同尺寸落位 | 一次工作流执行产整包素材；程序化生成器保底 |
| **音频流水线** | agent + Floniks | TextToMusic 生成 BGM（锁 BPM/调性）、音效族（升调 combo 链）、TTS 语音 | 三声道规范；`audio_manifest.json` 可重放 |
| **宣发流水线** | agent + Floniks/Pixify | 截屏关键帧 → 图生视频 → 节拍剪辑 → 15s/30s 预告片；Web 传播页 | App Store 物料 + 可分享链接 |

规则三条：

1. **玩法数值永远在 Lua**——调手感不重编 Rust（仓库既有约定）；引擎流水线只在 profiler 证明必要时启动；
2. **每条流水线的产出必须过无头测试**才能进集成分支——包括美术（manifest 校验尺寸/命名）和音频（时长/响度）；
3. **关键选型用双流水线对照**（M0 两个原型、重要机制 A/B 两版实现）——这是我们独有的、已被 PR #47 验证过的工作方式。

## 四、开发计划：五个里程碑

总排期 **5 周**（每周一个里程碑），每个里程碑以"制作人可玩的东西"收口，绝不以文档收口。
工作粒度沿用 agent-loop 节拍：每项 = 一个 issue = 分解→实现→测试→回归→PR，单项目标耗时分钟级到小时级。

### M0 · 数学核心对决（3 天）—— "先证明好玩"

- 《星核熔炉》与《萤火牧歌》各出一个 **graybox 原型**（纯色块，零美术，`packs/` drop-in）；
- 每个原型配齐第一批不变量测试（forge：质量守恒/能量有界/聚变单调/无隧穿；boids：群不解体/无重叠/速度上限）；
- 性能基准：真机 Release 与 Web 各跑 500 实体压力场景；
- **验收：制作人各玩 20 局，按"10 秒可懂 / 30 秒爽点 / 还想再来一局"三问打分，定唯一主玩法**。
  落选者归档为普通 mini-game 保留。

### M1 · 核心循环完成（1 周）—— "单局成立"

- 完整单局：投放节奏、下一个预告（Suika 式）、危险线告警、失败/结算/即时重开；
- **Juice 第一遍**：命中三件套（粒子+音效+缓动）全事件覆盖、连锁 combo 升调、shake/zoom punch/触觉分级；
- 难度曲线 v1：随场上总质量收紧的动态压力；
- `game.track` 埋点：局长、失败原因、连锁深度、重开率；
- **验收：无头跑 10 万帧零违约；单局中位时长落 1–3 分钟；制作人连玩 10 局不弃**。

### M2 · meta 层（1 周）—— "第二天还想开"

- 本地存档 meta：元素图鉴（聚变链收集）、永久升级树（3–5 个节点起步）、成就；
- **日期种子每日挑战**（同日全球同种子，种子进测试参数化——每日关自动可回归）;
- meta 分层露出：首日仅核心循环+一条升级线，图鉴/每日在第 3–5 会话解锁;
- 教学 = 前三局的引导投放（无文字教程，靠关卡设计教学）；
- **验收：新档→解锁全 meta 的无头脚本通过；存档杀进程回读一致；制作人次日主动回访**。

### M3 · 视觉与听觉完成度（1 周）—— "像个商业产品"

- 风格圣经定稿 → Floniks 工作流一次执行产整包素材（星核 10 级 + UI + 背景元素），去背/放大/落位全自动；
- 背景 shader 专属主题：energy 接"场上总质量"，反应扩散彩蛋斑纹；聚变碎屑用黄金角排布；
- TextToMusic 生成 BGM（分菜单/局内/高压三段，同 BPM 家族）+ 全套音效族 + 结算 TTS 语音；
- CJK 文案进 `subset_font.py` STRINGS 表；设置页（音量三通道/触觉/HUD）；
- **验收：占位素材清零；`ART_REQUESTS.md` 关闭;一致性评审（Floniks consistencyEval ≥ 85 分）**。

### M4 · 完整度与上架（1 周）—— "交付"

- Web 构建上线（一条链接可玩，传播主渠道）+ TestFlight 包；
- 预告片管线：真实录屏关键帧 → 图生视频 → 节拍剪辑 → 15s/30s 两版 + 商店截图文案；
- 埋点复盘：用 M1 的 track 数据调难度/节奏最后一遍；性能验收（真机 120Hz、Web 60fps）；
- **验收：G1–G5 逐条对账全绿 = §六 全量门禁（A–F）通过 + 玩家旅程 28 条走查零红项；
  第一批外部玩家（≥10 人）经 Web 链接完成 ≥3 局，playtest 问卷"半成品感"零提及**。

### 风险与对冲

| 风险 | 对冲 |
|---|---|
| M0 两个原型都"不好玩" | 循环短（3 天），换下一组合方向（引力轨道《引力邮差》为板凳首选）；meta/juice/管线工作全部可复用 |
| Lua 侧 O(n²) 碰撞在 Web（ottavino）掉帧 | 先空间哈希（Lua 实现，词法作用域内 50 行）；仍不够则引擎流水线开 `game.field()` 批处理洞（Rust 侧一个 LuaCommand 的既有套路） |
| AI 素材风格漂移 | 风格圣经 + consistencyEval 门禁 + 程序化生成器永远保底（游戏任何时刻可跑） |
| 范围蔓延 | 每里程碑以"可玩"收口；新想法一律进 backlog issue，不插队当前里程碑 |

## 五、迭代节奏

- **分钟级**：Lua 热重载调数值（引擎不重编）；单个不变量测试秒级跑。
- **小时级（agent loop）**：一个 issue = 分解→实现→测试→回归→PR→squash 合并。这是已实测的节拍
  （roadmap §5：单项 2.5–14 分钟，复杂玩法项预估 1–4 小时）。
- **天级**：每日集成 = `make test` 全量（Rust 单测 + Lua 不变量）+ Web 构建刷新 → **制作人每日 playtest**，
  反馈当天进 issue。数据（`game.track` 本地日志）随 playtest 一起看。
- **周级**：里程碑验收（上文逐条）→ go/no-go → 下周 issue 树刷新。每周产一版可分享 Web 链接，
  从 M1 起就让外部玩家进来——**playtest 半径每周扩大一圈**（自己→朋友→外部）。
- **工具节拍**：Issue 驱动开发（复杂任务先建 issue、checklist 实时勾选）；PR 默认 draft、squash 合并；
  测试行数随功能行数同步增长；每次合并前全量回归——全部沿用两仓库既有规范。

## 六、质量标准：AAA 级完成度门禁

> 两路补充调研（2026-07-07）：**玩家完成度感知研究** + **AAA 评级/认证标准研究**。
> 结论先行：(1) "AAA"的可复制部分不是预算，是**生产价值与打磨密度**——媒体评分维度收敛为
> 玩法手感/视觉/音频/内容量/技术表现，主机 TRC/XR 认证与 Google/Apple 的质量阈值给出了硬数字
> （[Metacritic 分档](https://metacritichelp.zendesk.com/hc/en-us/articles/15456550496023)、

> (2) 玩家对完成度的判断形成于**前 10 分钟**——底部四分位手游第 5 分钟即流失 46% 新玩家，头部仅 17%
> （[Google Play 数据](https://medium.com/googleplaydev/why-the-first-ten-minutes-is-crucial-if-you-want-to-keep-players-coming-back-to-your-mobile-game-4a89031b6308)）；

### 6.1 六类量化门禁（逐条可测，M4 出厂全绿）

**A. 技术性能**
- A1 用户感知崩溃率 <0.5%（Google 坏行为线 1.09% 的一半），ANR/hang 率 <0.47%
- A2 冷启动到可交互 ≤400ms（[WWDC19 标准](https://developer.apple.com/videos/play/wwdc2019/423/)）；进入任一游戏 ≤2s 无黑屏
- A3 真机 Release 120Hz（ProMotion）稳定，最低支持机型 1% Low ≥55fps；Web 端 60fps
- A4 主线程单次阻塞 <250ms；大 `dt` 帧不引发瞬移/穿隧（既有 `test_pong.lua` 传统，扩展到新玩法）
- A5 任意时刻杀进程/来电中断后恢复，进度不丢（对标主机 suspend-resume 认证项；`game.save` 已具备）
- A6 内存峰值 ≤ 最低支持机型可用内存 60%，无泄漏

**B. 视觉**
- B1 统一调色板/网格/字体，占位素材清零（App Review 2.1 红线：占位内容即拒审）
- B2 所有状态变化有缓动过渡，关键交互 100ms 内有视觉反馈；按钮有按压态
- B3 像素艺术 nearest 采样无模糊；全分辨率 + 刘海安全区适配无裁切
- B4 每次击打/得分/失败 juice 三件套（粒子+震屏或 zoom punch+闪色）全事件覆盖

**C. 音频**
- C1 100% 交互有音效；同帧去重、音乐不重叠不重启（三声道规则已实现，转为验收项）
- C2 BGM 循环无接缝爆音；三通道独立音量并持久化
- C3 静音键/来电/拔耳机正确暂停恢复；Web 首次手势解锁音频（已处理，保持）

**D. 交互手感**
- D1 触控目标 ≥44pt；输入到画面响应 ≤1 帧
- D2 触觉分级使用（light/medium/heavy/success 已接入），强度与事件重要性匹配、不滥用
- D3 失败 ≤1 次点击立即重试；任何界面 ≤2 步回菜单，零 softlock

**E. 内容完整性**
- E1 完整闭环：隐式教学 → 难度曲线 → 结算 → 重玩钩子，无 dead-end、无"敬请期待"（4.2 红线）
- E2 失败画面有尊严感：清晰结算（得分/最佳/进度）、鼓励性文案、失败后不立即插打断
- E3 空状态/断网/中断等边缘情况全部有体面处理
- E4 Lua 错误不致命、玩家无感知降级（既有约定，转为验收项）

**F. 无障碍与本地化**
- F1 正文对比度 ≥4.5:1；关键信息不单靠颜色区分（如绿/红球加形状记号，色盲可玩）（[XAG 104](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/104)）
- F2 提示/字幕字号 ≥18px；提供减少屏震/闪烁开关（防光敏晕动——`game.shake` 加全局系数即可）
- F3 目标语言 100% 覆盖零机翻感；CJK 全部进 `subset_font.py` 子集，零"豆腐块"

### 6.2 玩家旅程检查表（前 10 分钟定生死）

出厂前按玩家旅程逐条走查（完整 28 条清单沉淀为 `tools/RELEASE_CHECKLIST.md`，M4 建档）：
**商店页**（图标小尺寸可辨、截图真实、描述与实际一致）→ **首启**（≤5s 冷启动、无强制弹窗、首屏即可交互）→
**首局**（30 秒内进核心玩法、教程可跳过、零错字零占位）→ **失败**（结算画面、一键重开、不羞辱）→
**回访**（杀进程回读一致、每日挑战新鲜感）→ **卸载前防线**（设置齐全、退出有收尾的被尊重感）。

### 6.3 门禁如何进流程

- **每条门禁尽量测试化**：A4/A5/E4/F3 直接进无头测试；B1/C1 进 manifest 校验脚本；
  A2/A3 进真机验收脚本读 FPS overlay。不能自动化的（B2/E2/旅程走查）进 RELEASE_CHECKLIST 人工项。
- **里程碑逐级背负**：M1 出厂背 A4/B4/C1/D3（手感层），M2 背 A5/E1/E2（闭环层），
  M3 背 B/C/F 全部（视听与无障碍层），M4 全量门禁 + 旅程走查。**不把 polish 堆到最后一周**——
  但 M3+M4 两周（占总周期 40%）本身就是行业 20–30% polish 占比的加强版。
- **playtest 问卷加两问**："哪里感觉像半成品？""哪个细节让你觉得用心？"——直接对应
  完成度感知研究里的负面/正面清单。
