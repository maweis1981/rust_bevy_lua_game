## 对决双方

立项方案定的规则：**不开会选玩法，做两个原型打一架**。两个候选各由一条（组）数学公式驱动，
graybox 阶段零新美术——现有 `orb`/`sparkle` 纹理 + 纯色 tint，所有预算花在"是否好玩"上。

### 《星核熔炉》Starforge（`packs/forge.lua`，~300 行 Lua）

两条公式的耦合：

```
引力    a = GM / r²          （所有星体坠向中心引力井）
聚变    a + a → 2a           （同级星体相撞合并，质量翻倍）
耦合    GM = GM₀ · (1 + Σm / 220)   （场上总质量越大，引力越强）
```

单指点按，星体在点按处自动入圆轨（v = √(GM/r)，切向）。同级相撞聚变（动量守恒、2ⁿ 计分、
连锁 combo）；异级相撞弹性弹开。**耦合项就是难度曲线**：每次聚变都让全场轨道收紧，
老轨道的速度逐渐"不够用"而向内螺旋——你亲手造出的星越重，系统越危险。
坠入视界喂大黑洞（GM 再涨一档，失去一个核心，三个核心 = 三条命）；甩出屏幕则白白损失。
L10+L10 = 超新星：双星湮灭，+2048 分，全场减压。

### 《萤火牧歌》Fireflies（`packs/fireflies.lua`，~280 行 Lua）

Craig Reynolds 的 boids 三规则 + 一个追光项：

```
分离：太近就推开    对齐：靠拢邻居的航向    凝聚：飞向邻居的质心
追光：手指按下时，指尖是唯一光源，全群趋光
```

没有任何直接控制——你不操纵任何一只萤火虫，只能用光**间接**放牧整群。
把足够比例的群保持在光环内 1 秒得分；每次得分光环换位并新增一张蛛网；
碰到蛛网的萤火虫被粘住损失；群体损耗到 8 只以下则终局。

## 测试即验收

`tools/test_m0_packs.lua`（约 320 行）延续本仓库的无头测试传统——mock 掉 Rust `game` API，
直接驱动真实的游戏脚本数千帧，断言**数学契约**而不是实现细节：

- **Starforge**：单星圆轨 1200 帧不坠不逃（漂移 < 30px）；同轨双 L1 星必然聚变为 L2 且加分；
  6000 帧随机注入长跑中——速度永不过 620 上限、等级恒在 1..10、每颗星 `m = 2^(level-1)`、
  总质量账目守恒（well 吃掉的质量不凭空消失）、实体数 ≤ 48、全程无 NaN；
  0.25s 的大 dt 卡顿帧不产生瞬移；游戏结束后一次点击必然重开且分数归零。
- **Fireflies**：光源定在中心 900 帧后全群平均散布 ≤ 150px（凝聚性）；无蛛网阶段零伤亡；
  把群赶进光环必然在限时内得分、每次得分必然生成蛛网；把群停在蛛网上必然损耗；
  损耗最终触发终局、重开后满编 40 只；速度上限、边界、NaN、大 dt 同上。

首次全量：**238,332 checks，一次通过**；既有 130,331 条旧断言无回归。
新测试已挂进 `make test`。这不是运气——两个原型都是先写不变量清单再写玩法的。

## 为什么这么快

与 07-07 引擎冲刺同一个原因：**架构把每件事都摊薄了**。原型 = 一个 drop-in Lua 文件
（PACK_SPEC 契约），物理/群体各自 ~60 行核心数学，其余是计分与 juice 调用（粒子/震屏/
zoom punch/触觉全是现成的 `game.*` 一行）。Web 端只需在显式 pack 列表加两行。

## 第二轮（同日）：机器人先玩，数据说话

真人 playtest 之前，先让机器人玩（[#62](https://github.com/maweis1981/rust_bevy_lua_game/issues/62)）。
`tools/tune_m0.lua` 用三种脚本手无头快进：**随机手**（随机点投放）、**瞄准手**（贴着现有星体投放、
主动追求聚变）、**追环手**（fireflies 贪婪追光环）。每策略 20 局，统计单局时长与得分分布。

第一版数据很难看：**forge 单局中位 20.8s**（目标 60–180s）。两处死亡螺旋：
吞噬全额反哺 GM（越死越难死得更快）、`MIN_SPAWN_R=76` 允许贴视界的自杀投放。
三处修正后（吞噬只消化一半质量、安全投放半径 76→120、`MASS_SCALE` 220→700）：

| 策略 | 单局中位 | 得分中位 | 得分率 |
|---|---|---|---|
| forge/随机手 | 57.8s | 188 | ~3/s |
| forge/瞄准手 | 28.9s | 500 | ~17/s |
| fireflies/追环手 | 57.7s | 3 环 | — |

瞄准手死得更快但得分率是随机手的 **6 倍**——"追求聚变=主动冒险"的风险收益张力恰好是设计想要的。
fireflies 加了每 3 环孵化 3 只援军的希望机制。同轮还加了：近视界红色预警、下一星预览球、
combo 显示、光环充能增亮、蛛网脉冲、双方最高分 `game.save` 持久化。

全量重跑：**425,228 checks 全绿**（局变长了断言自然变多）。

## 第三轮（同日）：M1 提前开跑 — 按住瞄准、结算卡、隐式教学

对决判定未到，按方案主推位规则先行推进 Starforge 的 M1（[#65](https://github.com/maweis1981/rust_bevy_lua_game/issues/65)）：

- **输入模型升级**：点按投放 → **按住瞄准（幽灵星 + 切向轨迹点）、松手投放**。
  无效位置（太近黑洞/冷却中）幽灵变暗——投放从赌变成决策。测试与机器人同步换模型。
- **图形结算卡**：`set_text` 三行字 → 面板 + SCORE/BEST/TOP STAR + "FORGE AGAIN" 按钮
  （门禁 E2：失败画面的尊严感 + 一键重开）。
- **隐式教学**：前 3 局固定发牌 `1,1,1,2,2,3`——新玩家 30 秒内必然见到第一次聚变（门禁 E1）。
- **聚变闪白帧 + L5+ zoom punch 分级**：爽点强度对应事件重要性。
- **物理再调参**：瓶颈不是引力耦合而是**拥挤度**（异级弹撞扰轨道）。弹性 0.86→0.7、
  新增"星云软墙"（越界改为弹簧拉回，逃逸变成漂亮的椭圆回归而非白白损失）、核心 3→4。
  换真人节奏（1.2s/投）的机器人重测：**随机手 66.9s / 瞄准手 60.8s（偶有 300s 长局）——
  双双进入 60–180s 目标带**，且高手上限存在。
- **`tools/report_analytics.py`**：读 analytics.log 出局长/死因/聚变/combo 分布——
  真人 playtest 完，一条命令出复盘表。
- 途中修了一个**测试自身的坑**：旧聚变断言依赖两颗星的轨道相位巧合，重写为结构性必然相撞
  （第二颗投在第一颗当前位置径向外 12px）。脆弱的测试比没有测试更危险。

全量：417k+ 断言绿，旧套件无回归。

## 第四轮（同日）：M2 提前铺轨 — 引擎开洞、每日挑战、元素图鉴

M1 工程项清空后（拖尾、双游戏结算卡对齐已在途中补完），loop 转入 M2 的三连击：

- **引擎开洞 `game.date_utc()`**（[#63](https://github.com/maweis1981/rust_bevy_lua_game/issues/63)）：
  读路径三步走的又一次教科书式复用——Bridge 快照 + 双后端注册（mlua/ottavino 同形）+
  Howard Hinnant 纯函数日期算法（6 组已知日期单测，含闰日与跨日翻转）。
  wasm 无 SystemTime，web 端走 `js_sys::Date`。桌面 + wasm 双目标编译验证。
- **每日挑战**（[#67](https://github.com/maweis1981/rust_bevy_lua_game/issues/67)）：
  日期 → 独立 LCG → **同日全球同一副牌**（Suika/Balatro 的通行做法）。DAILY chip 一键切换，
  每日最佳按 `forge_daily_YYYYMMDD` 独立存档。确定性直接进断言：同日两次运行的
  8 张发牌逐一相等。这就是"每日关卡自动可回归"的含金量——**每日内容不需要人出题，
  但每天的题全球一致、且永远可测**。
- **元素图鉴**（[#68](https://github.com/maweis1981/rust_bevy_lua_game/issues/68)）：
  每级聚变（L2→L10 + 超新星）永久落账，结算卡上一排 10 格星核——点亮的彩色、
  没点亮的暗格。"还差两格"就是下一局的理由（品类调研里的收集钩子，最便宜的实现）。

途中顺手处理了一次**与 main 的合并冲突**（另一条 agent 流水线同日合入了 Time Dodge/Craft World，
wasm pack 列表双边追加撞行）——三包并集、slot 无撞号、全量回归后消解。

至此方案里 M2 的"每日挑战 + 收集"两个 meta 件已在 graybox 上跑通，
全部只用 `game.save/load` 本地 KV——**零后端**，与调研结论一致。

## 第五轮（同日）：M3 执行 — 制作人一句"批准"，AI 素材整包落位

M2 收尾（升级树 [#69](https://github.com/maweis1981/rust_bevy_lua_game/issues/69) + 成就×6）后，
制作人批准了 M3 生成（[#71](https://github.com/maweis1981/rust_bevy_lua_game/issues/71)）。执行记录：

- **两条可重放 Floniks 工作流**：图像（文生图 nano-banana-2 → 去背 → 输出）、
  BGM（Lyria 2 → 转码 → 输出）。工作流 id 与全部 prompt 沉淀在
  `tools/floniks_m3_manifest.json`——重 roll 一次 = 重放一次。
- **7 张图落位**：熔岩星核底图（灰度裂纹发光，十级 tint 全兼容）、吸积环、瞄准环、
  三个升级图标（熔核/星云盾/星轨箭头）、金色星尘货币图标。菜单图标同步换新。
- **BGM 双轨压力系统**：同一主题（96bpm/D 小调）的沉稳版与高压版，
  **场上总质量 >300 切高压、<200 回沉稳**——音乐第一次成为玩法状态的函数，
  与背景 shader 的 energy 通道同一设计哲学。
- **诚实的取舍**（全记录在 manifest 的 rejected 字段）：柔光粒子被去背吃掉→保留程序化版；
  orb 是跨游戏共享纹理→forge 用独立 forge_star 避免污染；平台 textToAudio 是 TTS 不是
  音效模型→SFX 保留合成版。**程序化生成器永远是保底**，这是方案定下的对冲，今天用上了。
- 实际消耗：约 205 积分（预算内），余额 10.6 万。全量回归 422k 断言绿。
