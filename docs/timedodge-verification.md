# Time Dodge 设计验证报告（2026-07-07）

无 GPU 容器内的两层验证：**真实 wasm 构建 + 无头 Chromium 截图**验证视觉与流程；
**自动驾驶 AI 实测**（mock 宿主、逐帧驱动真实 `timedodge.lua`）定量验证玩法。
验证脚本：临时 autopilot sweep（结论固化于此文档与星级阈值）；截图：`make web` +
Playwright。

## 视觉验证结论

- ✅ 菜单、模式选择页、关卡页、局内（玩家/拖尾/时之门/HUD/敌人）在真实 wasm
  构建里全部正确渲染；单游戏包（AUTOBOOT）直接进入游戏、无大厅菜单。
- ⚠️ 无头 SwiftShader 软件 WebGL 下极光背景退化为浅蓝（与 `docs/web-poc/`
  历史基准一致，**容器限制而非缺陷**）；GPU 环境为 WGSL 定义的深色极光。
- 🔧 已修：深冻结时敌人颜色 94% 插到冰蓝导致种类不可读 → 色彩插值上限 55%；
  关卡页标题与返回按钮重叠 → 标题下移；菜单 slot 撞号（craft/timedodge 均为
  10）导致磁贴顺序每次启动随机 → timedodge 改 11 + 排序按 key 平局裁决。

## 玩法验证结论（自动驾驶 sweep）

**无尽模式**（12 个种子、闪避 AI、上限 180s）：
存活偷时 min 8.6 / median ~50 / max 86 秒（AI 为帧级完美反应，人类约取其
1/3~1/2，落在超休闲 15–60s 会话区间）；5 种敌人的觉醒通告在 10/20/30/45
偷秒精确触发。

**试炼模式**（寻门 AI、≤5 次重试；调优后最终值）：

| 关 | 专家线用时 | 死亡 | 星级阈值 s3/s2 |
|---|---|---|---|
| 1 | 2.3s | 0 | 4/7 |
| 2 | 2.6s | 0 | 5/8 |
| 3 | 4.4s | 0 | 8/13 |
| 4 | 3.6s | 0 | 7/11 |
| 5 | 4.9s | 0 | 9/14 |
| 6 | 6.3s | 0 | 11/18 |
| 7 | 13.5s | 0 | 23/38 |
| 8 | 7.5s | 0 | 13/21 |
| 9 | 18.5s | 0 | 32/52 |
| 10 | 13.4s | 1 | 23/38 |

阈值 = 专家线 ×1.7（三星）/ ×2.8（两星）。验证驱动的三轮调优：
① 初版门距过近 + 无开局弹压 → 全关 1–5s 直通三星（形同虚设）→ 门改最远点
采样（硬约束的兜底会把门放到玩家脚边）+ 每关开局齐射 + 弹幕加密；
② lv9 智能弹占比 75% 连专家 AI 都 6 连死 → dart 权重加倍、齐射 6→4；
③ 阈值按实测重标。

**反龟缩**：冻结为 6% 流速而非绝对时停——lv1 纯龟缩约 50s 后仍被爬行弹磨死
（"the clock only forgives the dead" 名副其实）；lv9 有恒动者，龟缩 3 秒内死。

## 验证后落地的玩法修改（用户反馈）

- **时间规则改为"按住=流动，松手=冻结"**（原为"移动才流动"）：更符合手机
  操作直觉，冻结成为一个明确的"松手"动作；文案/测试/素材管线同步更新。
- **敌人初速上调**：无尽 240→320 px/s 起步；试炼各关 +40。
- 相对拖动（手指不遮挡角色）与 820px/s 防瞬移上限维持不变。
